# Offline Arabic Text Summarization Module

Phase 1 MVP: an offline abstractive summarizer for Modern Standard Arabic news and
organizational reports (300–1000 words → a 10–30% summary, 30–300 words) that runs on a CPU.
Persian summary: [`docs/README.fa.md`](docs/README.fa.md). Design: [`docs/architecture.md`](docs/architecture.md).
Status and every decision: [`PROGRESS.md`](PROGRESS.md). **New contributors: start with [`docs/HANDOFF.md`](docs/HANDOFF.md).**

## Repository layout

| Path | What it is |
|---|---|
| `src/arabic_summ/` | the package: data, text processing, pipeline, training, optimization, evaluation, app |
| `configs/default.yaml` | every setting (paths, data, pipeline, fine-tuning, optimization, evaluation, models) |
| `notebooks/01…05` | thin Colab drivers, generated by `tools/build_notebooks.py` (edit the builder, not the `.ipynb`) |
| `bench/run_bench.py` | acceptance benchmark for the offline CPU machine |
| `tests/` | CPU unit tests, including tiny-model training / export / app runs |
| `requirements/` | pinned extras per environment (see below) |
| `docs/reference_guideline.md` | how benchmark references are written and reviewed |

Data, models and run outputs live on Google Drive under `DRIVE_ROOT` (default
`/content/drive/MyDrive/arabic_summ`), never in git.

## 1. Training and evaluation in Google Colab

Open a notebook from GitHub in Colab (`File → Open notebook → GitHub`, repo
`assaabriiii/Offline-Arabic-Text-Summarization-Module`), choose the runtime below, and run the cells in
order. Cell 0 clones the repo at `REPO_REF`, installs pinned extras, and records the environment.
Cell 1 mounts Drive. Cell 2 runs the unit tests. Every notebook is **resumable**: after a
disconnect, reconnect, run cells 0–1, then rerun the cell you were in.

| Notebook | Runtime | Does |
|---|---|---|
| `01_data` | CPU | XL-Sum download (pinned, SHA256-checked), dedup, benchmark items (240), leakage check, reference drafts import |
| `02_preprocess` | T4 | tokenizer calibration, chunking, pipeline smoke run |
| `03_finetune` | T4 | faithfulness filter, AraBART LR grid + final run, AraT5v2 comparison, decoding tuning, export with provenance, GPU-hour ledger |
| `04_optimize` | CPU | PyTorch / ONNX × FP32 / INT8, isolated measurement, proposal gates + composite score, export `models/arabart_ft_cpu` |
| `05_evaluate` | T4 | all systems on the benchmark, ROUGE with CIs, fact check, latency, BERTScore, blind human-evaluation sheets, acceptance report |

Set `REPO_REF` to a commit SHA in cell 0 for a fully reproducible run. For a private fork, add a
Colab secret `GITHUB_TOKEN`.

## 2. Offline CPU machine: install

Reference machine (proposal): x86-64, ≥ 8 cores, 16 GB RAM, SSD, **Python 3.13**.

On a connected machine with the same OS, CPU architecture and Python version, download the wheels:

```bash
git clone https://github.com/assaabriiii/Offline-Arabic-Text-Summarization-Module.git
cd Offline-Arabic-Text-Summarization-Module
pip download -r requirements/cpu-runtime.txt -d wheelhouse --extra-index-url https://download.pytorch.org/whl/cpu
```

Copy the repo folder, `wheelhouse/`, and the exported model folder `models/arabart_ft_cpu/`
(from Drive) to the offline machine, then:

```bash
python3.13 -m venv .venv && source .venv/bin/activate
pip install --no-index --find-links wheelhouse -r requirements/cpu-runtime.txt
pip install --no-deps -e .
```

The model folder is self-contained: weights (PyTorch or ONNX), tokenizer, `decoding.json`,
`runtime.json` and `provenance.json` (SHA256 of every file).

## 3. Use

```bash
# summarize a UTF-8 text file (or pipe text with --input -)
python -m arabic_summ summarize --model-dir models/arabart_ft_cpu --input article.txt
python -m arabic_summ summarize --model-dir models/arabart_ft_cpu --input article.txt --ratio 0.25 --json

# local web UI on http://127.0.0.1:7860 (not exposed to the network)
python -m arabic_summ serve --model-dir models/arabart_ft_cpu
```

Options: `--ratio` 0.10–0.30 (default 0.20), `--strategy` `segmentwise` (default) | `hybrid` |
`direct` | `extractive` | `lead`, and `--threads`. The Hugging Face offline switches are set before
loading, so no network call is attempted. Every result reports input/output words, the allowed range,
time, and any **number in the summary that does not occur in the input**.

## 4. Acceptance benchmark (offline machine, network disabled)

```bash
python bench/run_bench.py --model-dir models/arabart_ft_cpu \
    --texts benchmark_items.csv --out bench_out
```

`--texts` takes `benchmark_items.csv` (selected rows) or a JSONL with `sample_id`, `text`.
The runner uses batch size 1 with the model preloaded and one warm-up call. It records CPU model,
threads, OS, warm-up time, per-sample input length and latency, peak process memory, weight size
and an outbound-network probe. It writes `bench_out/bench_report.json` and exits non-zero if any
hard criterion fails: median ≤ 15 s for 300–700 words, ≤ 25 s for 300–1000 words, RAM ≤ 8 GB,
model ≤ 1 GB, and every output within 10–30%.

## 5. Development

```bash
pip install -e ".[test]" && pytest            # CPU, ~30 s
python tools/build_notebooks.py               # after editing notebook cells
ARABIC_SUMM_ORT_PYTHON=/path/to/py313-with-cpu-runtime/bin/python pytest   # also runs the ONNX export test
```

Environments: training uses Colab's transformers 5 plus `requirements/colab-data.txt`. ONNX export
and the offline runtime use `requirements/colab-onnx.txt` / `requirements/cpu-runtime.txt`
(transformers 4.57.6, which optimum-onnx requires). Tokenizers saved by transformers 5 load there
through a fallback.
